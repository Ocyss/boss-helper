# AI 提示词与知识分层设计

> 状态：共享事实配置与三任务注入已编码，等待人工验证<br>
> 更新日期：2026-08-12

## 结论

已有知识、AI 招呼规则和 AI 筛选条件不应全部重复写进每套 Prompt。Prompt 只负责本任务的判断方法和输出契约；长期候选人事实应维护一份，按任务注入必要子集；可确定执行的限制应由代码和配置兜底。

当前实现已将原 `aiReply.knowledge` 提升为 `candidateProfile.knowledge`。每条事实的适用任务、自动回复授权、来源、确认日期和有效期均由配置决定；AI 筛选、AI 招呼和 AI 回复分别按自己的检索策略选取事实。旧回复知识会迁移为仅供回复使用，不会自动扩大到筛选或招呼；迁移完成后配置只写入共享字段，不再维护第二份副本。

## 当前能力与目标边界

- AI 回复支持配置化“部分可答”策略：模型通过 `needsHumanReview` 和 `unansweredTopics` 标记被避开的薪资、详细住址、具体时间等主题。运行时协议独立追加到用户 Prompt，因此重新导入自定义 Prompt 不会关闭该协议；是否启用由回复策略配置决定。

| 能力 | 当前状态 | 目标 |
| --- | --- | --- |
| AI 回复证据 | 按消息和岗位关键词选取已授权事实；自动模式额外要求 `autoReplyAllowed` | 增加事实与回复语义一致性的二次校验 |
| AI 招呼输出 | 依赖 Prompt 约束，生成后直接进入发送阶段 | 由代码校验空值、单行、说明前缀、禁词和长度 |
| AI 筛选输出 | 解析 `negative/positive` 并计算净分，阈值读取配置 | 使用 schema 校验整数、范围、唯一维度和硬排除结构 |
| 共享候选人事实 | 已实现统一配置、旧知识迁移、任务授权、关键词/顺序检索和条数限制 | 增加更细的检索评测与冲突检测 |

当前配置已经支持 `keywords`、`source`、`confirmedAt`、`validUntil`、`tasks` 和 `autoReplyAllowed`。结构化有效期由代码过滤；旧知识正文中的唯一绝对有效期会在迁移时提取。关键词检索是轻量确定性匹配，无命中时按用户配置顺序兜底，尚未引入向量检索。若共享事实与旧 Prompt 冲突，当前模型仍可能收到两种口径，因此三份旧 Prompt 中复制的候选人事实需要在下一阶段移除。

## 五层职责

1. **共享已确认事实**：项目经历、真实技术栈、指标、学历、年限、地点和面试偏好。只维护一份；事实变更后统一生效。
2. **任务 Prompt**：角色、目标、判断原则、评分维度、表达风格和输出 schema。AI 筛选、AI 招呼、AI 回复各自独立。
3. **运行时载荷**：本轮 JD、岗位字段、当前日期、HR 信息和可见聊天记录。每次调用动态注入，不写死在 Prompt。
4. **用户策略配置**：投递阈值、目标方向、硬排除开关、招呼长度和回复模式。Prompt 引用实际配置值，不重复写固定数字。
5. **代码校验与风控**：JSON/schema、分数范围、字数、证据标签、日上限、频控熔断、发送队列和消息版本检查。其中回复证据、长度、泄露和发送风控已有基础实现；招呼与筛选的完整 schema 校验仍待开发。

## AI 招呼 Prompt 评估

现有 Prompt 的方向正确：先展示 JD 匹配点、只选一个项目和少量技术、限制指标使用、禁止虚构，并要求自然沟通邀请。主要问题是九项候选人事实与知识库重复维护；`140` 字和“只输出单行字符串”也不能只靠模型自觉。

建议保留“前 20 字高信息量”“一项项目 + 一项证据”“最多三个技术关键词”“不讨论薪资福利”等生成规则。候选人事实改为从共享资料检索 3～5 条与 JD 最相关的证据；后续补充代码校验，拒绝空值、换行、说明性前缀和超长内容。指标只有在事实已确认且与 JD 直接相关时才注入。

## AI 筛选 Prompt 评估

现有 Prompt 的高召回方向、语言可迁移原则、硬排除与普通扣分区分都合理，但同一规则在“不投递岗位”“专项判断”“硬排除”“评分校准”中多次重复，输入较长，会增加延迟、成本和模型自相矛盾概率。

建议将明确且无歧义的岗位规则先交给本地预过滤；“有实习经验优先”“负责部署上线”等包含关键词但并非排除条件的反例不能用简单 `includes` 判断。语义不明确时再交给 AI。AI Prompt 只保留一次硬排除定义、四个加分维度、五类普通扣分及禁止臆测规则。投递线读取当前 `aiFiltering.score`，不要在 Prompt 中写死 `50`。输出继续使用 `negative/positive`；整数、范围、硬排除结构和最终净分的确定性校验列为后续任务。

## 推荐调用结构

```text
system: 本任务规则 + 输出契约
candidate: 本任务需要的已确认事实子集
policy: 当前阈值、目标方向和启用的硬规则
job: 本轮岗位字段与 JD 原文
```

AI 筛选只需要能力摘要和求职策略；AI 招呼需要与 JD 最相关的项目证据；AI 回复需要聊天问题涉及的事实。三者不应默认携带整份知识库。

回复决策中的 `evidenceIds` 只供插件内部校验，不属于聊天话术。HR 可见 `reply` 必须是自然纯文本；若出现 `[K01]`、`【K01】`、`[knowledge:K01]` 等内部标记，插件直接转人工，不做字符串删除后继续发送。
