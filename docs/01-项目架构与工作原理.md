# BossHelper 工作原理与反爬机制调研

> 调研日期：2026-08-11
> 目的：为拓展功能提供代码层面的认知基础

## 一、项目概览

Boss直聘助手（BossHelper）——面向 BOSS 直聘网站的浏览器扩展，用于批量投递、筛选岗位、AI 打招呼。基于 **WXT + Vue3 + NuxtUI@4 + TailwindCSS@4**，支持 Chrome / Edge / Firefox 三端。仅供学习交流，禁止商用。

## 二、整体架构：三层隔离 + 跨 world 通信

```
┌─ 页面 MAIN world（与站点 JS 同上下文）────────────────┐
│  boss.js  ← 核心业务：数据获取、投递、AI、UI          │
│  (src/entrypoints/boss/index.ts)                     │
└──────────────┬───────────────────────────────────────┘
        comctx defineProxy（__boss-helper-content__）
┌──────────────▼───────────────────────────────────────┐
│  content.ts（ISOLATED world）→ 注入脚本 + 代理中转     │
└──────────────┬───────────────────────────────────────┘
        comctx defineProxy（__boss-helper-background__）
┌──────────────▼───────────────────────────────────────┐
│  background.ts → storage / 网络 / 通知 等浏览器能力   │
└──────────────────────────────────────────────────────┘
```

### 2.1 各层职责

| 层         | 文件                            | 职责                                                                         |
| ---------- | ------------------------------- | ---------------------------------------------------------------------------- |
| MAIN world | `src/entrypoints/boss/index.ts` | 核心业务入口，定义 `BossHelperCtx`，挂载 `boss-helper-job` 自定义元素        |
| ISOLATED   | `src/entrypoints/content.ts`    | 匹配 `*://*.zhipin.com/*`，`document_start` 注入 `boss.js`，注册 comctx 代理 |
| 后台       | `src/entrypoints/background.ts` | storage / 网络 / 通知等浏览器能力，注册 `BackgroundCounter`                  |

### 2.2 关键设计点

- **ISOLATED world 拿不到站点 JS 的任何对象**（`__vue__`、window 变量、cookie），所以核心逻辑必须放 MAIN world。这是为什么 `boss.js` 作为 unlisted script 注入而不是直接写 content script。
- **跨 world 通信**由 [comctx](https://www.npmjs.com/package/comctx) `defineProxy` 实现：boss 脚本 → ContentCounter → BackgroundCounter 逐层代理。
- **`src/message/index.ts` 的 `counter` 是惰性代理**：使用前必须调用 `initCounter()`，否则抛错（`src/message/index.ts:20-47`）。
- **UI 渲染**：`src/index.ts` 的 `run(ctx)` 定义自定义元素，Shadow DOM + 内联 CSS 隔离站点样式，`HelperKey` 注入 ctx。UI 组件在 `src/components/`（Tabs 下为配置/日志/统计等页面）。

## 三、数据获取：不解析 DOM，直接 Hook 站点的 Vue 实例（核心机制）

`src/composables/useVue.ts` 是整个项目最核心的机制：

### 3.1 三个基础能力

1. **`getRootVue()`**：轮询 `#wrap.__vue__` 拿到 BOSS 站点根 Vue 实例（Vue 2 的 `__vue__` 属性挂在 DOM 元素上，`useVue.ts:18`）。超时 20s 抛「未找到vue根组件」。
2. **`useHookVueData(selector, key, ref)`**：读取站点组件 `__vue__` 上的数据字段（如 `jobList`、`jobDetail`），并 `Object.defineProperty` **劫持其 setter**（`useVue.ts:61-67`）——站点更新数据时同步到本地 ref，扩展与站点共享同一份数据源。
3. **`useHookVueFn(selector, key)`**：**直接调用站点内部函数**，如 `pageChangeAction`（翻页）、`searchJobAction`（搜索）、`clickJobCardAction`（点击职位卡片触发详情加载）。

### 3.2 站点侧依赖的关键数据/函数

`jobList`、`pageVo`、`hasMore`、`jobDetail`、`clickJobCardAction`、`pageChangeAction`、`searchJobAction`、`onSearch`。

> ⚠️ **BOSS 站点前端改版导致这些 hook 失效，是此类扩展最常见的故障模式**。报错信息「未找到vue根组件」「pageChange is undefined」（`src/entrypoints/boss/index.ts:139` 的 `_pageChange` 抛错）即源于此。

## 四、反爬应对策略分析

### 4.1 设计思路

项目不"破解"任何接口，而是**站在站点代码内部读取和操作**，天然避开多数反爬检测：

| 常见反爬手段                                    | 本项目的应对                                                                   |
| ----------------------------------------------- | ------------------------------------------------------------------------------ |
| 接口加密参数（`securityId`、`encryptJobId` 等） | 不自己造请求，复用站点内部函数/数据，参数自然正确                              |
| 检测自动化（无头浏览器、CDP 特征）              | 真实浏览器 + 真实用户会话，无自动化痕迹                                        |
| 检测扩展注入（隔离 world 的痕迹）               | MAIN world 注入，与站点脚本同上下文，扩展边界不可见                            |
| 数据加密/混淆后才返回                           | 拿到的是 Vue 内部**已解密的结构化数据**（`jobList` 数组），比 DOM 解析更全更快 |
| 站点改版导致 DOM/接口变更                       | hook `__vue__` 和组件方法名，DOM 结构改动不敏感                                |

### 4.2 投递动作也走站点逻辑

- 「岗位详情获取」任务调用 `ctx.helper.onJobCardClick()`（`src/entrypoints/boss/delivery.ts:38-46`），让站点自己的逻辑加载详情。
- 「岗位投递」复用站点请求里的 `securityId` + `encryptJobId`（`delivery.ts:75-84`）。

### 4.3 遗留风险点

- **hook 依赖站点内部字段/方法名**，改版即失效（最大风险）。
- **`defineProperty` 劫持、Shadow DOM 注入**理论上可被站点检测（detection 面：函数调用栈、DOM 属性差异）。
- **高频操作是风控触发的最常见原因**：投递/打招呼速率控制至关重要。

## 五、投递工作流：DAG 任务管线

`src/entrypoints/boss/delivery.ts:16-104` 声明完整任务链，任务带 `deps` 依赖；`src/composables/useApplying/` 的 `useDeliveryWorkflow` 构建期做拓扑排序并检测环，运行期按 `before → handler → after` 执行，抛 `DependencyMissingError` 时自动重跑依赖任务，`meginResults` 合并多任务结果。

### 5.1 任务链一览

```
列表过滤（不耗请求）：已沟通 → 同公司 → 同HR → 岗位名 → 公司名 → 薪资 → 规模 → 猎头
        ↓
岗位详情获取（调站点 onJobCardClick 触发）
        ↓（依赖详情的过滤，命中即 skip，不浪费投递）
活跃度 → HR职位 → 地址 → 好友状态 → 内容 → 金牌HR → 高德地图 → AI筛选
        ↓
岗位投递（复用站点 securityId 发投递请求）
        ↓
Boss信息获取 → 自定义/AI 招呼语
```

### 5.2 设计要点

- **过滤前置低消耗、后置高消耗**：详情获取之后才跑依赖详情的过滤，命中 `taskResult.skip`，全过才真正投递。
- **结果缓存**：`PipelineCacheManager`（IndexedDB，`src/composables/useApplying/usePipelineCache.ts`）避免重复请求——重复请求本身也是风控判定特征之一。
- **任务实现注册**：`src/composables/useApplying/handles.ts` 的 `TaskRegistry`，AI 筛选在 `useModel` 之上。

## 六、其他子系统

### 6.1 配置系统（`src/composables/conf/`）

- reactive `FormData` + `useStorageAsync`（经 counter 代理写入扩展 storage）。
- 支持多配置预设切换（key 形如 `local:web-geek-job-FormData-${preset}`）。
- 配置结构迁移通过 `FROM_VERSION` 版本迁移表（时间戳版本号，见 `info.ts`）。
- UI 配置页由 `getConfigItems()` 声明式描述（`src/components/Tabs/Config.vue` 渲染）。

### 6.2 HelperContext 抽象（`src/composables/useHelper/ctx.ts`）

泛型抽象类 `HelperContext<C, T, S>` 抽象所有站点能力：`jobList`/`jobMaps`、`uid`/`userInfo`、`onMount`、`sendMessage`、`getConfigItems`、`workflow`、`statistics`、`logs`、`models`、`netConf`。UI 通过 Vue provide/inject（`HelperKey`）获取 ctx。目前唯一实现是 `BossHelperCtx`。

### 6.3 聊天（`src/entrypoints/boss/chat/`）

`GeekChatClientManager` 基于打包的 geek-chat-core（BOSS 的 MQTT 聊天协议），消息经 `publish('chat', ...)` 发送，文本/图片消息由 `sendMessage` 处理。

### 6.4 AI（`src/composables/useModel/`）

基于 AI SDK（`ai` / `@ai-sdk/openai`），多模型管理，支撑 AI 筛选与 AI 打招呼。

## 七、拓展功能的纪律建议

1. **拿新数据优先 Hook，不要新增接口调用**：新数据先看站点 Vue 实例有没有现成字段，或复用站点已有函数。直连接口会引入 `securityId`/签名问题，增加风控暴露面。
2. **投递/消息频率控制**：投递、打招呼加间隔和随机抖动，全速跑是风控触发的最常见原因。
3. **新能力挂到 `HelperContext` 抽象层**：新能力（收藏、沟通记录导出等）注册到 ctx，UI 侧通过 `getConfigItems()` 声明式配置，保持 `BossHelperCtx` 与通用逻辑解耦。
4. **新任务注册到 `TaskRegistry`**：筛选类逻辑放 `src/composables/useApplying/handles.ts`，在 `delivery.ts` 声明依赖链——注意别把新任务放在投递之前造成无谓消耗。
5. **改版防护**：站点的 `jobList`/`pageChangeAction` 等关键 hook 失效时报错信息要能快速定位是哪个字段没了（当前 `useVue.ts` 统一报「未找到对应元素」，定位粒度可细化）。
