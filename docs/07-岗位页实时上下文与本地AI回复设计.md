# 岗位页实时上下文与本地 AI 回复设计

> 状态：MVP 已编码，待人工验证<br>
> 更新日期：2026-08-12

## 数据来源

岗位页加载时调用关系接口读取最多 100 个已聊 HR 及最后一条摘要，随后由现有 BOSS MQTT/WS 增量接收文本。用户选择会话或触发 AI 时，再按需调用 `/wapi/zpchat/geek/historyMsg` 读取最近两页记录；每条消息按 `mid` 去重，并用 `friendId + friendSource` 映射到 ChatBox 会话。

处理前，插件先用 `getBossData()` 补充会话对应岗位摘要，再从历史岗位卡、当前 `jobMaps` 和岗位接口补充 JD。调用 `getJobDetail()` 时只使用真实 `lid`；没有 `lid` 时改用 `securityId` 查询并回退到岗位基础信息，不伪造字段。

## 模型上下文

每轮最多提供最近 24 条本地可见消息、当前批次 HR 新消息、岗位字段及最多 50 条已启用且已确认的本地知识。岗位、消息和知识分别生成 `job`、`message:<id>`、`knowledge:<id>` 证据 ID。主动跟进使用独立触发类型，提示模型承接已有对话并避免重复开场或刚发送的内容。

ChatBox 默认宽度为 900px，并至少按 900px 展示；宽度直接应用到 `USlideover` 的 `content` 面板，覆盖组件默认的 `max-w-md`，窄视口下仍受 `96vw` 限制。左侧使用头像、姓名、最近消息和未读徽标组成纵向会话列表，支持按 HR、公司、岗位或已加载消息搜索，并可切换“全部 / 未读 / 已读”。右侧展示当前聊天、历史读取状态、岗位上下文状态以及“处理当前消息”“主动跟进”两个动作。消息区使用独立滚动容器，打开 ChatBox 时的自动置底不会再改变岗位页滚动位置；连接状态仍在后台维护，但不展示“WS 已连接”卡片。

“AI 模型配置”的导入导出只包含模型连接参数。AI 自动回复提示词和知识库属于全局业务配置，需要在“配置”页先保存，再使用“导出配置 / 导入配置”迁移。

自动回复设置另支持导入约定结构的 Markdown。导入器分别读取“系统提示词”“调用载荷建议”和 `[K01] 标题` 格式的知识卡，不会把整份文档当作一条知识。知识默认按稳定 ID 合并，提示词替换默认关闭；只有用户预览并确认文件内容后，导入知识才标记为已确认并可进入模型上下文。文件内 ID 冲突、空内容或超出条数/长度限制时拒绝导入，不静默覆盖或截断。

未读状态优先使用接口返回值，并按 BOSS Chat SDK 的 `uncount/status/direction` 规则接收 WS 增量；离线同步消息只更新未读状态，不触发 AI。打开会话后插件清零本地未读数，并通过现有 WS 发送已读回执。尚未完成状态同步的会话只显示在“全部”中，不会被误判为已读。

当前没有完整历史接口，因此 `conversationHistoryComplete` 固定为“不完整”。用户手动选择已有会话时，触发上下文会注明“无本次新消息”，模型只能根据当前可见记录判断是否适合主动跟进。

## 处理规则

- HR 连续文本等待 2.5 秒后合并；不同会话互不阻塞。
- 同一会话的模型任务串行执行，避免回复顺序错乱。
- 只有 HR 实时入站消息可按自动模式在本地校验和配置延迟后通过原 WS 直发；用户点击“处理当前消息”或“主动跟进”始终先生成草稿。
- 模型生成或发送等待期间若最后一条消息 ID 已变化，旧结果作废并转人工。
- 草稿模式先展示并允许复制；“确认发送”按钮本身即代表用户授权，不再弹浏览器二次确认。发送成功后先在 ChatBox 本地回显，再用 WS 回环的服务端消息 ID 去重校正。
- `evidenceIds` 仅用于插件内部确定性校验；如果 `reply` 含证据编号、内部字段或引用标签，则整次结果校验失败并转人工，不允许带标记发送给 HR。
- 不确定或异常会持久化暂停会话；暂停期间新消息仅触发人工通知。

## 生命周期限制

接收器仍属于岗位页页面脚本。关闭标签页、退出登录、浏览器休眠或 BOSS 协议变化都可能中断实时处理。MVP 不承诺浏览器关闭后的后台常驻回复。
