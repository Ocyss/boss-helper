# 小白使用说明

这份文档写给第一次使用 Chrome 扩展、第一次接触 AI API、第一次用 BOSS 直聘自动化投递的人。

如果你已经很熟悉浏览器扩展、API Key、LLM、Prompt，可以直接看 [README](../README.md)。如果你看不懂 README 里的词，先看这一份。

> [!CAUTION]
> 本工具只能辅助你筛选岗位、批量投递和生成招呼语。自动化操作可能触发 BOSS 直聘风控，存在账号异常、权重降低、黑号或封号风险。
>
> 第一次使用时，请先用很小的数量测试，例如 3 到 5 个岗位。不要一上来就投满每天上限。

## 先理解几个词

| 词 | 简单解释 |
| --- | --- |
| Chrome | 谷歌浏览器。这个工具目前主要按 Chrome 扩展方式使用。 |
| 扩展程序 | 安装在浏览器里的小工具，类似给浏览器加一个功能插件。 |
| 未打包扩展 | 开发者模式下加载的扩展文件夹。普通用户下载发布版 zip，解压后选择里面有 `manifest.json` 的文件夹。 |
| AI | 人工智能。这里主要用于判断岗位是否合适、帮你写招呼语。 |
| LLM | 大语言模型。你可以简单理解成 DeepSeek、ChatGPT 这类会写文字的 AI。 |
| API | 给软件调用 AI 的接口。你在网页上聊天是手动用 AI，API 是让这个工具自动请求 AI。 |
| API Key | API 的钥匙。谁拿到这个 Key，谁就可能消耗你的余额，所以不要发给别人。 |
| Prompt | 你给 AI 的任务说明。比如“请根据岗位信息写一段求职招呼语”。 |
| Token | AI 计费单位。可以粗略理解成文字片段，输入和输出都会消耗 Token。 |

## 最推荐的使用顺序

1. 安装 Chrome。
2. 加载扩展。
3. 登录 BOSS 直聘网页端。
4. 先不用 AI，只用普通筛选和自定义招呼语，投 3 到 5 个岗位测试。
5. 确认基础投递正常后，再配置 DeepSeek API。
6. 配置 AI 招呼语或 AI 筛选。
7. 每次修改配置后，点「保存配置」。
8. 每次批量投递后，进入聊天页检查「话术发送」面板。

不要跳过第 4 步。先让最简单的流程跑通，再加 AI，排查问题会轻松很多。

## 安装 Chrome

如果你电脑里没有 Chrome：

1. 打开 Chrome 官方下载页：[https://www.google.com/chrome/](https://www.google.com/chrome/)
2. 点击下载。
3. 下载完成后安装。
4. 打开 Chrome。
5. 用 Chrome 登录 BOSS 直聘网页端：[https://www.zhipin.com/](https://www.zhipin.com/)

建议使用电脑网页端，不要用手机 App 来测试这个工具。

## 加载扩展

### 普通用户：下载已构建版本

普通用户不要下载源码，也不需要自己找 `.output` 文件夹。

请打开 GitHub 发布页：

[https://github.com/ZhuYiwen020118/boss-helper-ai-greeting/releases/latest](https://github.com/ZhuYiwen020118/boss-helper-ai-greeting/releases/latest)

在页面里找到类似下面名字的文件：

```text
boss-helper-ai-greeting-chrome-mv3-custom-0.4.4-stable.3.zip
```

下载这个 zip 文件，然后解压。

解压后，你会得到一个文件夹。打开这个文件夹，如果能看到 `manifest.json`，说明找对了。

然后在 Chrome 里加载：

1. 打开 Chrome。
2. 地址栏输入 `chrome://extensions/`。
3. 打开右上角「开发者模式」。
4. 点击「加载已解压的扩展程序」。
5. 选择刚才解压出来、里面直接能看到 `manifest.json` 的文件夹。

注意：

- 不要选择 Git 仓库根目录。
- 不要选择单个 `.js` 或 `.json` 文件。
- Chrome 要加载的是包含 `manifest.json` 的整个文件夹。
- 如果你看到的是压缩包本身，先解压，不要直接选 zip。

### 开发者：从源码构建

只有开发者才需要从源码构建。源码构建后才会出现 `.output/chrome-mv3` 文件夹：

```bash
pnpm install
pnpm build:chrome
```

构建完成后，在 Chrome 里选择 `.output/chrome-mv3` 文件夹加载。

如果你不懂命令行，请使用上面的 Release zip，不要走源码构建流程。

## 最重要的概念：两层漏斗

这个工具有两层筛选，不要混在一起理解。

### 第一层：筛选 Tab

「筛选」Tab 里放的是 BOSS 直聘网页原本自带的搜索和筛选条件。

它决定的是：页面下面先出现哪一批岗位卡片。

例如：

- 搜索关键词：前端、产品经理、Java、数据分析
- 城市：上海、深圳、广州
- 薪资：10-15K、15-25K
- 经验：1-3 年、3-5 年
- 学历：本科、大专
- 公司规模、行业、融资阶段等

你可以把它理解成第一张网：先让 BOSS 直聘给你捞出一批大概相关的岗位。

### 第二层：配置 Tab

「配置」Tab 是这个工具自己的规则。

它决定的是：对第一层筛出来的每一个岗位，再逐个判断要不要投。

例如：

- 公司名包含某些词就不投。
- 岗位名必须包含某些词才投。
- 岗位内容出现“销售”“外包”“驻场”就过滤掉。
- HR 职位必须是经理、主管、老板才投。
- 工作地址必须包含某些区域。
- 薪资必须在你能接受的范围。
- Boss 最近不活跃就过滤掉。
- 已经聊过的 HR 不再重复投。
- AI 判断分数太低就过滤掉。

你可以把它理解成第二张网：对已经出现的岗位卡片做精细过滤。

推荐流程：

1. 先在「筛选」Tab 里把大方向选好。
2. 再在「配置」Tab 里把不想要的岗位排掉。
3. 最后去「统计」Tab 点「开始」。

## 帮助模式

主面板最后有一个「帮助」勾选框。

勾选后，把鼠标移动到某个按钮或配置项上，会显示原作者写的提示文案。

这份小白说明会把主要配置项都展开解释。如果你还是不确定某个按钮是什么，可以同时打开「帮助」模式对照看。

## 统计 Tab

「统计」Tab 是开始投递和查看进度的地方。

### 数据指标

| 指标 | 含义 |
| --- | --- |
| 岗位总数 | 今天脚本扫描过的岗位数量。 |
| 过滤比例 | 被过滤掉的岗位比例。数据不一定绝对准确，只能辅助判断。 |
| 沟通比例 | 已经沟通过的岗位比例。 |
| 活跃比例 | 因 Boss 不活跃被过滤的比例。 |
| 近三日/本周/本月/历史投递 | 按时间范围统计投递数量。 |

### 按钮

| 按钮 | 作用 |
| --- | --- |
| 开始 | 开始批量处理当前页面的岗位。 |
| 暂停 | 正在投递时暂停。 |
| 重置筛选 | 把已经被筛选过但未成功投递的岗位重置为等待状态，方便重新处理。 |

### 进度条

进度条表示当天已投递数量占投递上限的比例。

默认投递上限通常建议设置在 120 左右，不建议接近平台极限。

## 筛选 Tab

「筛选」Tab 主要是 BOSS 直聘自己的搜索栏和筛选条件。这个工具会把它们搬到 Helper 面板里，方便你和工具配置一起操作。

常见用法：

1. 先输入岗位关键词，例如 `前端`、`运营`、`数据分析`。
2. 选择城市和期望职位。
3. 选择 BOSS 自带的薪资、经验、学历等条件。
4. 等页面下面岗位列表刷新。
5. 再去「配置」Tab 设置更细的规则。

容易误解的点：

- 「筛选」Tab 不等于工具内部过滤规则。
- 这里改的是 BOSS 页面自己显示哪一批岗位。
- 如果第一层筛选太宽，后面配置页压力会更大。
- 如果第一层筛选太窄，可能没有足够岗位可投。

## 配置 Tab

「配置」Tab 是本工具最重要的设置页。

### 使用配置页的基本规则

1. 每个配置项前面的复选框要勾上，才会启用。
2. 有些项目可以在「包含」和「排除」之间切换。
3. 改完配置后要点「保存配置」。
4. 投递过程中配置会被锁住，避免边投边改造成混乱。
5. 看不到某些高级选项时，把「配置级别」调高。

### 配置级别

| 级别 | 适合谁 | 说明 |
| --- | --- | --- |
| 新手 | 第一次使用的人 | 只显示最基础配置，减少误操作。 |
| 初学者 | 用过几次的人 | 比新手多一点配置。 |
| 中级 | 大多数正常用户 | 推荐使用，能看到地址、薪资、投递数量等常用项。 |
| 高级 | 熟悉规则的人 | 会显示 AI、高德地图、清空配置等更危险或更复杂的功能。 |

如果你找不到「AI配置」「地址配置」「导入配置」「导出配置」「清空配置」，先检查配置级别。

### 筛选配置

#### 公司名

用于根据公司名称筛选。

| 模式 | 例子 | 效果 |
| --- | --- | --- |
| 排除 | 外包、咨询、培训 | 公司名里出现这些词就不投。 |
| 包含 | 腾讯、字节、阿里 | 只有公司名里出现这些词才投。 |

小白建议：先用「排除」模式，把明显不想投的公司类型写进去。

#### 岗位名

用于根据岗位标题筛选。

| 模式 | 例子 | 效果 |
| --- | --- | --- |
| 排除 | 销售、电话、客服 | 岗位名出现这些词就不投。 |
| 包含 | 前端、React、Vue | 岗位名必须出现这些词之一才投。 |

如果你找前端，可以用包含：`前端`、`Vue`、`React`。

#### 工作内容

用于根据岗位描述筛选。

常见排除词：

- 销售
- 电销
- 地推
- 外包
- 驻场
- 上门
- 贷款
- 催收
- 单休

这个项目会尝试处理一些否定语境，例如“不是外包”不一定会被当成外包过滤。但文本判断不可能百分百准确，重要岗位建议自己再看一眼。

#### HR 职位

用于根据 Boss/HR 的身份筛选。

常见选项：

- 经理
- 主管
- 法人
- 人力资源主管
- HR
- 招聘专员

包含模式表示：只投给这些身份的人。

如果你更想和业务负责人沟通，可以只保留经理、主管、法人；如果你希望范围更大，可以保留 HR、招聘专员。

#### 工作地址

只能是包含模式。

例如你只想去浦东、南山、天河，可以填：

- 浦东
- 南山
- 天河

岗位地址里必须包含其中一个词，才会继续处理。

#### 薪资范围

用于过滤薪资。

常见设置：

- `8-13K`
- `10-15K`
- `15-25K`

高级里有两种匹配方式：

| 模式 | 含义 |
| --- | --- |
| 宽松匹配 | 岗位薪资和你的范围有重叠就算符合。 |
| 严格匹配 | 岗位薪资要完整落在你的范围内才算符合。 |

小白建议先用宽松匹配，否则可能过滤掉太多岗位。

高级薪资还支持：

- 元/时
- 元/天
- 元/月

「同步」按钮会按固定算法把月薪换算成日薪和时薪。

#### 公司规模范围

用于按人数过滤公司。

例如：

- `20-99 人`
- `100-499 人`
- `500-2000 人`

如果你不确定，建议先不要启用。公司规模信息在平台上不一定非常精确。

#### 自定义招呼语

用于发送你自己写好的固定话术。

例子：

```text
您好，我对这个岗位比较感兴趣。我有相关项目经验，想进一步了解岗位要求和团队情况，方便的话可以聊一下吗？
```

建议：

1. 先关闭 BOSS 直聘自带默认招呼语，避免重复发送。
2. 再启用工具里的自定义招呼语。
3. 第一次只投少量岗位测试。

#### 招呼语变量

高级功能。

启用后，自定义招呼语可以根据岗位信息自动替换变量，例如岗位名、公司名、Boss 名称等。

如果你不懂模板语法，先不要打开。

#### 活跃度过滤

开启后，会过滤最近不活跃的 Boss。

建议打开。每天沟通次数有限，优先投给活跃的人更划算。

#### 猎头过滤

开启后，会过滤一些猎头发布的岗位。

是否打开取决于你的策略：

- 不想经过猎头：打开。
- 可以接受猎头岗位：关闭。

#### 好友过滤（已聊）

开启后，会过滤已经聊过的岗位或 HR。

建议打开，避免重复打扰同一个人。

#### 相同公司过滤

开启后，同一家公司投过后，后续同公司其他岗位会被过滤。

适合不想重复投同一家公司的人。

如果你愿意同一家公司多投几个岗位，可以关闭。

#### 相同 HR 过滤

开启后，同一个 HR 投过后，后续该 HR 其他岗位会被过滤。

建议打开，避免同一个 HR 收到多条重复沟通。

### 外观配置

这些不会影响投递逻辑，只影响页面显示。

| 选项 | 作用 |
| --- | --- |
| 隐藏头 | 隐藏 BOSS 页面顶部栏，让页面更清爽。 |
| 更换图标 | 把网页图标换成一个不那么明显的图标。 |
| 动态标题 | 浏览器标签标题显示当天投递进度。 |
| 模糊卡片 | 鼠标移动时显示卡片局部，偏视觉效果。 |
| 列表下沉 | 给岗位列表底部留空间，避免面板遮挡。 |

### 地址配置

地址配置依赖高德地图 API。小白可以先跳过。

如果你确实想按通勤距离过滤：

1. 去高德开放平台注册：[https://lbs.amap.com/dev/](https://lbs.amap.com/dev/)
2. 创建应用。
3. 添加 Key，类型选 Web 服务。
4. 把 Key 填到「高德地图key」。
5. 在「起点经纬度」里填你的出发位置。
6. 如果你填的是完整地址，可以点右侧按钮自动转经纬度。
7. 设置直线距离、驾车距离、驾车时间、步行距离或步行时间。

| 配置项 | 含义 |
| --- | --- |
| 启用 | 是否启用高德地图筛选。 |
| 高德地图key | 高德开放平台的 Key。 |
| 起点经纬度 | 你的出发位置，格式通常是 `经度,纬度`。 |
| 直线距离 | 公司和你的直线距离，单位 km。 |
| 驾车距离 | 驾车路线距离，单位 km。 |
| 驾车时间 | 预计驾车时间，单位分钟。 |
| 步行距离 | 步行路线距离，单位 km。 |
| 步行时间 | 预计步行时间，单位分钟。 |

把数值设为 `0` 通常表示不启用该项限制。

### AI 配置

如果配置级别是高级，会看到 AI 相关配置。

AI 主要有两个用途：

| 功能 | 作用 |
| --- | --- |
| AI 筛选 | 让 AI 根据岗位描述打分，分数太低就过滤。 |
| AI 招呼语 | 让 AI 根据岗位信息写一段更个性化的开场白。 |

AI 回复目前不要依赖。面试邀请和普通聊天不建议自动回复。

### 延迟配置

延迟配置用于降低操作频率，减少风控风险。

| 配置项 | 含义 |
| --- | --- |
| 投递开始 | 点击开始后等待多久再真正开始。 |
| 投递间隔 | 每个岗位之间间隔多久。 |
| 投递翻页 | 当前页面处理完后，翻下一页前等多久。 |
| 消息发送 | 目前未完整实现，不建议调整。 |

小白建议：不要把间隔调得太低。太快更容易被平台认为异常。

### 底部按钮和选项

| 按钮/选项 | 作用 |
| --- | --- |
| 配置级别 | 控制显示多少配置项。 |
| 发送通知 | 投递停止时发浏览器通知。 |
| 启用缓存 | 缓存处理结果，减少重复处理。该功能不建议小白优先使用。 |
| 清空缓存 | 清掉缓存结果。只有启用缓存时出现。 |
| 投递数量 | 今天最多处理多少个。建议先设 3 到 5 测试，再逐步增加。 |
| 保存配置 | 保存当前配置，并自动刷新页面。改完配置必须点。 |
| 重载配置 | 从本地重新读取配置。改乱了但还没保存时可以用。 |
| 使用推荐配置 | 应用项目内置推荐配置，不会覆盖主要筛选条件。 |
| 导出配置 | 把配置导出成文件，方便备份或发给别人。 |
| 导入配置 | 导入别人给你的配置文件。导入后要检查是否适合自己。 |
| 清空配置 | 清空当前配置。危险操作，谨慎使用。 |

## DeepSeek API 小白配置

如果你想使用 AI 招呼语或 AI 筛选，需要配置一个 AI 模型。

这里以 DeepSeek 为例。

> [!NOTE]
> DeepSeek 模型名和价格可能会变。以下信息按 2026-06-06 官方文档整理。使用前可以再看 DeepSeek 官方文档：
>
> - API 快速开始：[https://api-docs.deepseek.com/](https://api-docs.deepseek.com/)
> - 模型和价格：[https://api-docs.deepseek.com/quick_start/pricing](https://api-docs.deepseek.com/quick_start/pricing)

### 第一步：注册 DeepSeek 平台账号

1. 打开 DeepSeek 平台：[https://platform.deepseek.com/](https://platform.deepseek.com/)
2. 注册或登录账号。
3. 进入控制台。

### 第二步：充值

DeepSeek API 不是网页聊天，它会按 API 用量计费。

在平台里找到充值或余额页面，根据自己的实际使用少量充值。小白建议先小额充值测试，不要一次充太多。

官方价格页面说明：费用会按输入和输出 Token 计费，价格可能调整，实际以官方页面为准。

### 第三步：创建 API Key

1. 打开 API Key 页面：[https://platform.deepseek.com/api_keys](https://platform.deepseek.com/api_keys)
2. 点击创建 API Key。
3. 复制生成的 Key。
4. 把它保存在安全的地方。

注意：

- API Key 只给你自己用。
- 不要截图发到群里。
- 不要提交到 GitHub。
- 如果怀疑泄露，立刻去 DeepSeek 平台删除旧 Key，重新创建。

### 第四步：在工具里新建模型

回到 BOSS 直聘页面的 Helper 面板。

1. 打开「配置」Tab。
2. 把「配置级别」切到「高级」。
3. 找到「AI配置」。
4. 点击「模型配置」。
5. 点击「新建」。

在「创建AI模型」窗口里这样填：

| 字段 | 推荐填写 |
| --- | --- |
| 名称 | `DeepSeek V4 Flash` |
| 背景 | 随便选一个颜色，只影响显示。 |
| url | `https://api.deepseek.com/chat/completions` |
| model | `deepseek-v4-flash` |
| api_key | 粘贴你在 DeepSeek 平台复制的 API Key。 |

重要区别：

- DeepSeek 官方 SDK 文档里的 `base_url` 是 `https://api.deepseek.com`。
- 这个工具的 `url` 输入框要填完整接口地址，所以要填 `https://api.deepseek.com/chat/completions`。

模型选择：

| 模型 | 适合谁 |
| --- | --- |
| `deepseek-v4-flash` | 推荐小白使用，速度和成本更适合日常投递。 |
| `deepseek-v4-pro` | 更强但更贵，适合更复杂的分析。 |

如果下拉框里没有 `deepseek-v4-flash`，可以手动输入。这个输入框允许自定义模型名。

高级配置小白建议：

| 项 | 建议 |
| --- | --- |
| json | AI 筛选建议打开；AI 招呼语如果输出异常，可以关闭试试。 |
| stream | 保持关闭。 |
| temperature | 保持默认。 |
| top_p | 保持默认。 |
| presence_penalty | 保持默认。 |
| frequency_penalty | 保持默认。 |

填完后：

1. 可以点「测试」试一下模型是否能正常返回。
2. 点「保存」关闭创建窗口。
3. 回到「Ai模型配置」窗口，再点右下角「保存」。

很多人会漏掉第 3 步。模型列表窗口也要点「保存」。

## 配置 AI 招呼语

AI 招呼语的作用是：让 AI 根据岗位信息，帮你写一段更像真人的开场白。

操作步骤：

1. 打开「配置」Tab。
2. 配置级别选「高级」。
3. 打开「AI配置」。
4. 找到「AI招呼语」。
5. 点击它旁边的配置按钮。
6. 选择刚才创建的 DeepSeek 模型。
7. 选择「单对话模式」。
8. 填写 Prompt。
9. 点「测试」可以先看效果。
10. 点「保存」。
11. 回到 AI 配置区域，启用「AI招呼语」开关。
12. 回到配置页底部，点「保存配置」。

简单 Prompt 示例：

```text
你是一名求职者，请根据下面岗位信息，写一段自然、礼貌、简短的 BOSS 直聘开场白。

要求：
1. 不要超过 80 字。
2. 不要写成正式邮件。
3. 不要夸张，不要油腻。
4. 可以提到我对岗位感兴趣，并希望进一步沟通。
5. 只输出招呼语正文，不要解释。

岗位信息：
岗位名：{{ card.jobName }}
薪资：{{ card.salaryDesc }}
学历要求：{{ card.degreeName }}
技能要求：{{ data.skills }}
岗位标签：{{ card.jobLabels }}
岗位描述：{{ card.postDescription }}
```

如果你想让它更像你本人，可以把自己的经历写进去：

```text
我的背景：
我有 2 年前端开发经验，主要使用 Vue、React、TypeScript，做过后台系统和数据看板。

请根据我的背景和岗位信息，写一段自然的 BOSS 直聘开场白。
不要超过 80 字，只输出招呼语正文。

岗位信息：
岗位名：{{ card.jobName }}
薪资：{{ card.salaryDesc }}
技能要求：{{ data.skills }}
岗位描述：{{ card.postDescription }}
```

## 配置 AI 筛选

AI 筛选的作用是：让 AI 看岗位描述，判断这个岗位是否符合你的偏好。

操作步骤：

1. 打开「配置」Tab。
2. 配置级别选「高级」。
3. 打开「AI配置」。
4. 找到「AI筛选」。
5. 点击配置按钮。
6. 设置「过滤分数」。
7. 选择 DeepSeek 模型。
8. 填写 Prompt。
9. 点「测试」。
10. 点「保存」。
11. 启用「AI筛选」开关。
12. 回到配置页底部，点「保存配置」。

过滤分数可以理解成最低合格线。AI 给出的结果低于这个线，就会过滤。

简单 Prompt 示例：

```text
请根据我的求职偏好分析岗位是否适合我。

我的偏好：
- 加分：双休、早九晚五、技术栈现代、团队稳定、远程或通勤短
- 扣分：销售、电销、外包、驻场、单休、需要频繁出差、薪资明显偏低

请输出 JSON，格式如下：
{
  "positive": [
    { "reason": "加分原因", "score": 10 }
  ],
  "negative": [
    { "reason": "扣分原因", "score": 10 }
  ]
}

岗位信息：
岗位名：{{ card.jobName }}
薪资：{{ card.salaryDesc }}
经验要求：{{ card.experienceName }}
学历要求：{{ card.degreeName }}
福利：{{ data.welfareList }}
技能：{{ data.skills }}
岗位描述：{{ card.postDescription }}
```

小白建议：

- 先只开 AI 招呼语，不开 AI 筛选。
- 等你确认模型配置稳定后，再开 AI 筛选。
- AI 筛选会增加 API 消耗，因为每个岗位都可能要请求一次 AI。

## 话术发送面板

这是本 fork 新增的重要功能。

它主要解决这个问题：AI 招呼语或自定义招呼语已经生成，但 BOSS 页面发送通道变化，导致没有真正发出去。

### 它在哪里出现

在岗位页或搜索页，它可能嵌入 Helper 面板附近，提示你去聊天页发送。

在聊天页：

```text
https://www.zhipin.com/web/geek/chat
```

它会显示「话术发送」面板。

### 面板状态

| 显示 | 含义 |
| --- | --- |
| 就绪 | 当前可以操作。 |
| 发送中 | 正在按队列处理。 |
| 待发 | 还有几条队列内容没处理。 |
| 自定义话术 | 当前是否读取到了主 Helper 的自定义招呼语。 |
| 预览 | 即将发送或可发送的话术内容预览。 |

### 面板按钮

| 按钮 | 出现位置 | 作用 |
| --- | --- | --- |
| 去聊天页发送 | 岗位页/搜索页 | 跳转到 BOSS 聊天页。 |
| 开始发送 | 聊天页 | 手动开始处理待发队列。 |
| 停止 | 聊天页发送中 | 暂停当前发送流程。 |
| 发当前配置 | 聊天页 | 把主 Helper 里启用的自定义话术发到当前打开的聊天。 |
| 清空已发 | 聊天页 | 清空本地记录的已发送聊天对象。 |
| 诊断 | 全部 | 展开或收起诊断区域。 |
| 启用AI招呼语 | 诊断区域 | 尝试打开主配置里的 AI 招呼语开关并刷新页面。 |
| 显示队列JSON | 诊断区域 | 显示底层队列数据，方便排查。 |
| 清空队列 | 诊断区域 | 删除所有待发送队列。危险操作，谨慎使用。 |

### 安全行为

这个面板不会在聊天页加载后自动发送。你必须手动点「开始发送」。

队列发送时会尽量匹配目标 Boss：

- 找到目标 Boss：才会尝试发送。
- 找不到目标 Boss：暂停，不会随便发给其他人。
- 目标聊天已经有内容：跳过并标记完成，降低重复打扰风险。

### 常见场景

#### AI 生成了，但没发出去

1. 去「日志」Tab 看 AI 招呼语是否有响应。
2. 去聊天页。
3. 打开「话术发送」面板。
4. 看「待发」数量。
5. 点「诊断」查看 AI 配置状态。
6. 确认后点「开始发送」。

#### 只想手动给当前聊天发固定话术

1. 在「配置」Tab 启用自定义招呼语。
2. 保存配置。
3. 去聊天页打开某个聊天。
4. 点「发当前配置」。

| 项 | 建议 |
| --- | --- |
| 配置级别 | 中级 |
| 投递数量 | 3 到 5 |
| 活跃度过滤 | 开 |

5. 统计 Tab 点开始。
6. 去聊天页检查是否真的发出。
7. 没问题再加到 20、50、100。

## 常见问题

### 看不到 Helper 面板

可能原因：

- 没有用 Chrome。
- 扩展没有启用。
- 加载的不是包含 `manifest.json` 的解压后文件夹。
- 当前页面不是 BOSS 直聘网页端。
- 页面还没刷新。

解决：

1. 确认扩展已启用。
2. 重新打开 BOSS 页面。
3. 刷新网页。
4. 仍然不行就重新加载扩展。

### 配置了但没有生效

检查：

- 配置项前面的复选框有没有勾选。
- 是「包含」还是「排除」模式。
- 是否点了「保存配置」。
- 是否正在投递中，投递中配置会锁住。
- 配置级别是否太低导致你没看到某些选项。

### AI 模型测试失败

检查：

- DeepSeek 是否有余额。
- API Key 是否复制完整。
- URL 是否填成 `https://api.deepseek.com/chat/completions`。
- 模型名是否填成 `deepseek-v4-flash` 或 `deepseek-v4-pro`。
- 是否点了模型配置窗口里的「保存」。

### AI 招呼语没有生成

检查：

- AI 招呼语开关是否启用。
- AI 招呼语里是否选择了模型。
- Prompt 是否为空。
- 模型是否能在「测试」里正常返回。
- 日志里是否有错误信息。

### AI 生成了，但消息没发出去

这是本 fork 重点修的问题。

处理：

1. 去聊天页。
2. 看「话术发送」面板。
3. 展开「诊断」。
4. 如果有待发队列，确认内容后点「开始发送」。

### 过滤掉太多岗位

可能原因：

- BOSS 自带筛选太窄。
- 配置 Tab 里的规则太严格。
- 薪资用了严格匹配。
- 岗位名用了包含模式但关键词太少。
- 工作内容排除词太宽。
- AI 筛选分数线太高。

建议：

1. 先关掉 AI 筛选。
2. 减少工作内容排除词。
3. 薪资改宽松。
4. 投递数量设小一点重新测试。

### 投递到不想投的岗位

可能原因：

- 你只设置了 BOSS 筛选，没有设置工具配置。
- 配置项没勾选。
- 排除词没覆盖到该岗位。
- 岗位描述写得比较隐晦。

建议：

1. 去日志里看它为什么通过。
2. 补充公司名、岗位名或工作内容规则。
3. 小范围重新测试。

## 使用原则

1. 小范围测试。
2. 不懂的高级选项先别开。
3. 改配置后一定保存。
4. API Key 不要给别人。
5. 账号异常时立刻停止。
6. 不要让工具替你做所有判断，重要岗位仍然自己看。

这个工具适合帮你节省重复劳动，但最后要不要投、怎么沟通，仍然应该由你自己负责。
